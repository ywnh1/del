# del — 安全删除工具

[English](README.md) | **简体中文** · 📖 [使用手册](docs/guide.zh-CN.md)

> 带安全网的删除工具：文件先打包进回收站，之后随时可以恢复。

`del` 把删除拆成两个刻意的步骤 —— 软删除进回收站，以及显式运行 `--autoclean`
才真正释放磁盘空间 —— 并且用受保护路径列表和默认开启的 Safe Mode 托底。

## ✨ 亮点

**四重安全**，让 `rm` 的误删恐惧成为过去式：

| 层 | 说明 |
|----|------|
| ① | **回收站**：所有删除先进 `~/.trash`，随时 `-l` 查看、`-R` 恢复 |
| ② | **Safe Mode（默认开启）**：`--force` 被忽略，无法绕过回收站直接删除 |
| ③ | **Disable List**：系统关键路径（home、`/`、`/etc`、`/usr`、`/boot` 等）永不删除 |
| ④ | **延迟物理删除**：删除后数据仍安全存档，直到运行 `--autoclean` 才真正释放磁盘空间 |

**按内容寻址的归档**：每份归档按自身字节的 blake3 哈希命名，所以同一个未改动的路径重复删除会复用同一个文件，而不是堆出副本。哈希对应的是打包后的归档（tar 头 + zstd 帧），不是原文件内容 —— 详见[去重说明](docs/guide.zh-CN.md#82-去重到底是怎么工作的)。

---

## 为什么需要

`rm` 删除即消失：一次手滑、一个写错通配符、一段跑错目录的脚本，数据就没了。`del` 把删除拆成两步：

1. **软删除**：文件用 tar + zstd 打包进回收站，记录写入 SQLite，随时可以恢复；
2. **硬释放**：只有运行 `--autoclean` 才真正释放磁盘空间。

## 安装

需要 Rust 1.88 或更高版本（本 crate 使用 edition 2024，包括 let-chains）。

```bash
cargo install --path .
```

## 快速开始

```bash
# 删除一个文件（进回收站，原文件消失）
del ~/tmp/old-report.txt

# 查看回收站
del -l

# 把 1 号记录恢复到原位置
del -R 1

# 恢复并输出到其他目录
del -R 1 -o ~/Downloads

# 释放磁盘空间：清理过期记录 + 无引用归档
del -a

# 在终端 UI 里浏览并删除
del -t ~/Downloads
```

## 命令一览

`del -h` 给出每个选项的一行摘要，`del --help` 给出完整说明。

### 删除

| 命令 | 说明 |
|------|------|
| `del <path>...` | 打包进回收站并删除原文件 |
| `del -S <path>...` | 只打包进回收站，保留原文件（`--save`） |
| `del -f <path>...` | 永久删除（Safe Mode 下无效） |
| `del -f -r <dir>` | 永久删除整个目录树 |
| `del -t [path]` | 在 TUI 中浏览并删除（`path` 默认 `.`） |

TUI 键位：方向键移动，`Enter` / `→` 进入目录，`←` 返回上级，`d` 删除选中项（进回收站），`s` 打包（同 `-S`），`q` / `Esc` 退出。

### 回收站记录

| 命令 | 说明 |
|------|------|
| `del -l` | 列出全部记录 |
| `del -w <id>...` | 查看指定 id 的记录详情 |
| `del -x <pattern>...` | 按原路径包含的子串筛选记录 |
| `del -R <id>...` | 按 id 恢复记录 |
| `del -d <id>...` | 删除记录，归档文件保留 |

`-l`、`-w`、`-x` 的表格通过分页器显示：`q` 退出，`/` 搜索。

### 维护

| 命令 | 说明 |
|------|------|
| `del -a` | 清理回收站：过期记录 + 没有任何记录指向的归档 |
| `del -c` | 二次确认后清空全部记录（归档保留） |
| `del --level <n>` | 本次运行的 zstd 压缩级别（默认 3） |
| `del --save-time <days>` | `-a` 使用的保留天数（默认 30） |
| `del --trash-dir <dir>` | 指定回收站目录（默认 `~/.trash`） |
| `del --disable <path>,...` | 本次运行额外保护的路径 |
| `del -s` | 强制开启 Safe Mode |
| `del -v` | 打印调试日志，带 `文件:行号` 前缀 |

### id 语法

所有 id 参数共用同一套语法：

- `3`：单个 id
- `2,5,9`：逗号分隔多个
- `2-5` 或 `2~5`：闭区间
- `-5`：等价于 `0-5`；因为它以 `-` 开头，要用 `=` 形式传入：`del --show=-5` 或 `del -R=-5`
- 同一参数可以重复给：`del -R 1,2 -R 7`

数字、`,`、`-`、`~` 以外的字符会被忽略，所以从别处粘来的多行列表也能用。

## 配置

配置文件 `~/.config/del/config.toml`（可选）：

```toml
trash_dir = "/data/.trash"       # 回收站位置
safe_mode = true                 # 默认开启
compression_level = 6            # zstd 压缩级别（默认 3）
save_time = 30                   # autoclean 使用的保留天数
cover_mode = "ask"               # always / ask / never
disable_list = ["/boot", "/etc"] # 会整体替换内置保护列表
```

所有配置都可以用环境变量覆盖（前缀 `DEL_`，键名转小写，例如 `DEL_SAFE_MODE`、`DEL_TRASH_DIR`）。列表类配置使用 TOML 数组语法。

优先级：**CLI 参数 > 环境变量 > 配置文件 > 内置默认值**。

```bash
# 环境变量示例
DEL_TRASH_DIR=/data/.trash DEL_COVER_MODE=never del -l
DEL_DISABLE_LIST='["/boot","/etc"]' del /some/path
```

命令行只能**打开** Safe Mode（`-s`），没有关闭它的参数，所以想绕过回收站必须覆盖配置：

```bash
DEL_SAFE_MODE=false del -f ~/junk.log   # 真正删除，不进回收站
```

## 工作原理

```
删除 del <path>
  ├─ 1. tar + zstd 压缩打包
  ├─ 2. 按内容哈希命名 → ~/.trash/<hash>.bak
  │        （相同内容 → 同名 → 只存一份）
  ├─ 3. 记录进 SQLite（id / 原路径 / 归档路径 / 大小 / 时间）
  └─ 4. 移除原文件（-S 保留原文件）

恢复 del -R <id>
  ├─ 解包回原目录（或 -o 指定的目录）
  └─ 只有完全恢复后才删除记录；被覆盖策略跳过的条目保留记录，可重试

清理 del -a
  ├─ 第一遍：删除没有任何记录指向的归档文件
  └─ 第二遍：删除超过保留天数的记录
     （它们的归档会由下一次 -a 收集）
```

## 四重安全详解

1. **回收站（Trash）**：所有删除先进 `~/.trash`，`-l` 可查、`-R` 可恢复，删除不再是单向操作。
2. **Safe Mode（默认开启）**：`--force` 直接失效。命令行没有关闭它的参数 —— 在配置文件里写 `safe_mode = false`，或用 `DEL_SAFE_MODE=false` 运行。
3. **Disable List**：默认保护 `~/.trash`、home 目录与系统关键目录（`/`、`/boot`、`/etc`、`/usr`、`/var`、`/bin`、`/sbin`、`/lib`、`/lib64`、`/opt`、`/root`、`/home`、`/proc`、`/sys`、`/dev`、`/tmp`）。任何包含或等于受保护路径的删除目标都会被跳过并保留原样。`--disable a,b` 在列表上**追加**；配置文件里的 `disable_list` 则**整体替换**内置列表。
4. **延迟物理删除**：删除动作只是把数据搬进回收站，磁盘空间由 `--autoclean` 释放。`--delete` / `--clear` 只动记录，不动归档文件。

## 按内容寻址的归档

归档文件按 `<归档的 blake3>.bak` 命名。哈希取自打包后的字节 —— tar 流（条目名、权限、mtime）加上 zstd 帧 —— 而不是原文件内容。因此内容相同但文件名不同的两个文件会各存一份，而同一个未改动的路径重复删除只会复用一份。手册的[去重说明](docs/guide.zh-CN.md#82-去重到底是怎么工作的)把这套规则讲得更细。
